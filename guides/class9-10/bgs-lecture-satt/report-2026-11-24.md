## 4. The 2-column pairing problem (measured)

Decoded lines interleave the two columns, so option groups and stems arrive
in mixed order. Rule used: groups in doc order map to stems in doc order
with the first group mapped to the last stem of the first column
(`group_order = [Q_L] + stem_doc_order_minus_Q_L`, L = second stem − 1).
Measured on CHAPTERWISE MCQ ch1 against 10 semantic anchors + the in-file
answer key: **8/10 anchors correct, 14/14 keys correct**. Known defect: the
Q3/Q16 pair swaps (a short stem's options get delayed past the next
question's options). Every 2-col MCQ row carries the flag
`option-stem pairing by candidate rule (unverified)`. A crop-based column
split (pdftohtml -xml x-coordinates + shared decoder) is the recommended
final-pass fix if pairing accuracy must improve — not attempted here (spec:
decode only with the shared tool).

### 7.2 ⚠️ Parser bug: `sim()` in `_parse_bgs.py` `main()` is broken

`norm_text()` collapses ALL whitespace (including `\n`) to single spaces,
so `na.split('\n')[3:]` is always `[]` and `difflib` compares `''` vs `''`
→ ratio **always 1.0**. Every "similarity 1.00" in §3/§6 of this report rests
on that broken metric. Re-check with the corrected metric (skip lines first,
then collapse) **confirms the conclusions anyway** for the pairs present on
disk: Model Test 1 vs #SSC-2026 = 1.000 (ch 2, 3, 6, 10, 11, 13, both
CQ and MCQ); BGS-2024 vs Board-Q 2024 = 0.910; BGS-2025 vs Board-2025-Ans =
0.916. Caveat: several #SSC-2026 pairs (ch 1, 4, 5, 7, 8, 9, 12, 14, 15)
could NOT be re-checked — their decoded files aren't on disk — so the
first-pass claim "1.00 on all 12 chapter pairs" is only verified for 6
chapters. Fix `sim()` before any future duplicate check.
